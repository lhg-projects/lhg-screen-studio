# 边界：能学什么，别碰什么

## 可以自由学的（思路 / 架构 / 算法）

- 进程拓扑、tRPC router 设计、状态分层
- 录制状态机、崩溃恢复策略
- 缩放区间的数据结构与生成启发式
- 视觉合成的参数体系（背景/内边距/圆角/阴影的比例关系）
- 导出流水线的工程组织
- 授权的取舍逻辑（学思路，别照抄成"可控破解"）

**这些是知识，不是资产。学会它们不欠任何人。**

## 不要搬的（资产）

| 东西 | 位置 | 原因 |
|---|---|---|
| 字体 | `app.asar/assets/fonts/` | 商业授权字体，跟着应用分发的 |
| 音效 | `assets/sounds/`（点击音等） | 录音制品，有版权 |
| 图标 / 插画 | `assets/` | 美术资产 |
| 内置背景素材 | `assets/backgrounds/` | 摄影作品 |
| 内置光标集 | `assets/cursors/` | 美术资产 |
| UI 截图 / 宣传语 | 产品页 | 商标与文案 |

**判断标准很简单**：你能自己 5 分钟做出来的（一个圆角阴影参数、一条缓动曲线）→ 学；你需要找人画/录/买的（字体、音效、插画）→ 别碰。

## 灰色地带

- **代码逐行翻译**：逻辑不受版权保护，但"整体结构 + 变量命名 + 注释"的组合可能构成实质性相似。安全做法：**按规格重写**，而不是对着源码转写。
- **产品名 / 图标风格**：别做"XX Studio"这种近似名。
- **`node_modules` 里的 132 个包**：各有各的许可证（MIT 居多，少数 Apache/BSD），要复用时自己按包名重新拉，别从 asar 里拷。

## 一句话

**学它的判断力，别搬它的美术。** 这个应用最值钱的东西（缩放曲线怎么设计、崩溃恢复怎么做）都在代码逻辑里，而那些恰好是可以学的。
